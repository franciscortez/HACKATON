# URL to business dossier

Approved in conversation on 26 October 2026. A user pastes one business URL and receives a detailed business/visual-brand dossier and a separate one-page call sheet for pitching Leveric services.

Use bounded Apify browser extraction (six pages, one concurrent page, no retries, 120-second Actor, four-minute overall deadline). US$0.10 is a target, not a guaranteed spending ceiling. No external contact or competitor searches. Extract rendered HTML, visible text and observed styling; retain source excerpts and compact observations, not executable markup. Website colours/fonts are observations, not official brand guidelines.

The dossier covers offerings, audience, positioning, public proof, visual brand and up to three evidence-linked Leveric opportunities. Unknowns stay unknown. Model synthesis and proposed opportunities are labelled interpretations, not verified facts. The call sheet is independently editable; dossier edits invalidate it until an explicit rebuild. Approval gates exports; long print content is blocked rather than truncated.

Use a flowing white report with desktop evidence rail and mobile disclosures, keeping Leveric tokens/fonts. URL is the only required web input; pasted text remains recovery and the only source for local-only clients. Read view precedes editing. Accessible busy/cancel/error states, browser history, client isolation and legacy results must work.

Alternatives considered: website plus competitor research (rejected to prioritise the prospect); one-page-only output (rejected to retain depth); tabbed review (rejected for a flowing report); local browser infrastructure and HTML-only extraction (rejected in favour of bounded Apify rendering).

No database, deployment, automatic sending, technical audit, login scraping, commits or changes to other worktrees.
